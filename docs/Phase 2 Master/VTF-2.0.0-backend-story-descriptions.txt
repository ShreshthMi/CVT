########## VTF-331 (BE-01) — PDQ Parser: CQ-IR Subsheet ##########
==================================================================

*Context*
Parse the CQ-IR subsheet of the PDQ workbook into block-grouped {{cqIrParameters}} that mirror the Phase 1 {{userInput}} structure, so the existing engine path can consume PDQ-sourced reference values.

*Scope*
 - Drive parsing from the dedicated Config Key column: non-empty = parametric row (read Response, emit under that key); empty = meta row, skipped entirely.
 - Group every key under its CFG_* block, mirroring Phase 1 {{userInput}}.
 - Honour workbook visibility flags (hidden sheets/rows/columns are not parsed).

*Technical notes*
 - Value normalisation: split Response on first ':' (keep left, trim both sides); ' & ' splits arrays; IDENTIFICATION 'to' -> {{{min,max}}}; per-field step-division; INTERVAL enum-mapped; TIMEOUT_VALUE nested under CFG_TIMEOUT, step-divided, padded to 8.
 - The Remarks column is never read.
 - Project blocks (CFG_PROJECT_AEB / CFG_PROJECT_COM) and the version-aware group come from PDQ rows 1.08 / 1.09.
 - Single external error code {{PDQ_INVALID}}; internal enum variants drive logging only.

*Dependencies & blockers*
 - Feeds VTF-335 (preprocessor).
 - Open: Spring Boot 4.0.2 multipart override behaviour (B4).

*References*
Contract VTF-329.

*Acceptance criteria*
 - *Given* a CQ-IR sheet with populated Config Key rows, *When* parsed, *Then* each key is emitted under its CFG_* block with the normalised value.
 - *Given* a meta row (empty Config Key), *When* parsed, *Then* it is skipped regardless of Response content.
 - *Given* a parametric row with an empty Response, *When* parsed, *Then* the upload is rejected as {{PDQ_INVALID}}.

*Test/BDD*
Cucumber: happy path, each value-transform form, meta-row skip, malformed/empty-response rejection. Phase 1 features must still pass.

########## VTF-332 (BE-02) — PDQ Parser: ConfigControlTable + DT Inputs ##########
==================================================================

*Context*
Parse the ConfigControlTable subsheet (and the conditional Data Transmission Inputs subsheet) into the {{controlTable}} structure, matched to the parsed ADC files by DP name.

*Scope*
 - {{controlTable.trackSections[]}} from source cols A-H; {{controlTable.dpTable[]}} from cols J-M (col I is the empty boundary).
 - Match CCT rows to {{parsedConfigFile}} by exact case- and whitespace-sensitive DP-name comparison.
 - Return unmatched rows from either side as distinct categories - never silently dropped.
 - Data Transmission Inputs subsheet: absent -> {{dataTransmission: null}} (valid); present-but-empty -> reject as malformed; present-and-populated -> {{dataSafetyLevels[]}} + {{outputDataTransmission[]}}.

*Technical notes*
 - {{fadcAutoReset}} parsed as a structured logic tree (not a raw string).
 - DT-sheet SAFE_OUT_FDBCK_QUAD kept numeric 0/1; DT-sheet POSITION integer in [0,31] - distinct from the dpTable POSITION (ABOVE/BELOW THE RAIL).
 - Single external error code {{PDQ_INVALID}}.

*Dependencies & blockers*
 - Feeds VTF-335 (preprocessor) and every cluster story that reads the CCT.

*References*
Contract VTF-329.

*Acceptance criteria*
 - *Given* a ConfigControlTable with rows matching parsed ADC DP names, *When* parsed, *Then* trackSections[] and dpTable[] are populated and matched by literal DP name.
 - *Given* a DP-name differing only in case or whitespace, *When* matched, *Then* it is reported as unmatched, not coerced.
 - *Given* a present-but-empty DT Inputs sheet, *When* parsed, *Then* the upload is rejected as malformed.

*Test/BDD*
Cucumber: happy path, literal-match boundary (case/whitespace), unmatched-row categories, DT sheet absent/empty/populated.

########## VTF-333 (BE-03) — Baseline FCT Parser ##########
==================================================================

*Context*
Parse the uploaded Baseline FCT2 archive into the ComAebMap that the validate-time preprocessor consumes. The source of truth for CAN-segment membership.

*Scope*
 - Identify the archive: {{.fct2}} extension + ZIP magic-byte stream check (sample first 8-40 KB).
 - Parse {{Project.xml}} only, walking {{ProjectElements > Station > Cubicle > Rack > Bp}}.
 - Build CAN-segment membership from the {{Bp}} {{CanConnections}} previous/next chain.
 - Collapse MASTER/SLAVE redundancy (discard SLAVE, keep MASTER, set {{redundantComPresent: true}}).
 - Emit {{chains[]}} -> {{com}} + {{aebs[]}} ({{dpId}}, {{dpName}}, {{evaluatedFmas[]}}, {{acoIoExbs[]}} outputFma triplets, {{dtIoExbCount}}).

*Out of scope*
 - Trackplan XMLs inside the archive (only {{Project.xml}} is opened).
 - Counting-head-output mode IoExbs -> reject the upload.

*Technical notes*
 - {{dpId}} <- {{Aeb<Id>}}; {{dpName}} <- {{Aeb@cpName}}. ACO OutputFma resolved text -> {{Fma@internId}} -> {{Fma@aebInternId}} -> {{Aeb<Id>}}. All IDs serialised as strings.
 - Security limits: 10 MB file / 15 MB request / 20 MB threshold, 50:1 decompression cap, 50 MB uncompressed cap, 20 MB per-entry; nested-archive + password-protected rejection.
 - Two external error codes: {{FCT_TAMPERED}} (xref/invariant/XML-parse fail) and {{FCT_INCOMPLETE_BASELINE}} (dangling CanConnections, chain with no COM, etc.). Internal enum drives logging only.

*Dependencies & blockers*
 - Feeds VTF-335 (preprocessor).
 - Open: exact 8 root filenames + 2 folder names (B3); SB 4.0.2 multipart override (B4); counting-head-output rejection error-code mapping (B11).

*References*
Contract VTF-328.

*Acceptance criteria*
 - *Given* a valid FCT2, *When* uploaded, *Then* the ComAebMap is returned with one {{chains[]}} entry per CAN segment and redundancy collapsed.
 - *Given* an FCT2 containing a counting-head-output IoExb, *When* uploaded, *Then* it is rejected.
 - *Given* a manually edited / cross-reference-broken FCT2, *When* parsed, *Then* {{FCT_TAMPERED}} is returned.

*Test/BDD*
Cucumber: happy path, malformed archive, incomplete baseline, tampered xref.

########## VTF-334 (BE-04) — v2 Validate Endpoint and Coupled-Artifacts Gate ##########
==================================================================

*Context*
Add the Phase 2 validate endpoint and the coupled-artifacts gate; invoke the preprocessor and assemble the v2 response. The Phase 1 path stays untouched.

*Scope*
 - Add {{POST /api/config/v2/validate}}.
 - Coupled-artifacts gate: both FCT + PDQ -> v2; neither -> Phase 1 path; only one -> {{HTTP 400 PHASE2_INPUTS_INCOMPLETE}}.
 - {{userInput}} is upload-sourced: {{fctData}} + {{pdqData}} mandatory; four tpf keys (CFG_TROLLEY_SUPP, CFG_PARAM_TROLLEY_SUPP, CFG_RSR_TYPE, CFG_TYPE_PRTCT) optional when a tpf was uploaded.
 - Invoke the preprocessor (VTF-335) and assemble the response: {{validation_results[]}} (seven-field) + the eight detail tables; detail-cell {{_expected}} sibling on mismatch.

*Out of scope*
 - Phase 1 form keys are not sent on v2 (UI frozen). The tpf upload is independent of the gate.

*Technical notes*
 - Phase 1 {{POST /api/config/validate}} behaviour is preserved unchanged.
 - A zero-mismatch v2 response is shape-compatible with a Phase 1 response.

*Dependencies & blockers*
 - Depends on VTF-331, VTF-332, VTF-333 (parsers) and VTF-335 (preprocessor); response wiring shared with VTF-337.

*References*
Contract VTF-330.

*Acceptance criteria*
 - *Given* both uploads present, *When* validate is called, *Then* the v2 path runs and returns the v2 response shape.
 - *Given* only one upload present, *When* validate is called, *Then* {{HTTP 400 PHASE2_INPUTS_INCOMPLETE}}.
 - *Given* neither upload present, *When* validate is called, *Then* the Phase 1 path runs unchanged.

*Test/BDD*
Endpoint scenarios for all three gate states; tpf-present and tpf-absent; v2 response assembly.

########## VTF-335 (BE-05) — Validate-Time Preprocessor and Expectations JSON ##########
==================================================================

*Context*
Build the validate-time preprocessor that turns the FCT ComAebMap + parsed PDQ into the Expectations JSON the engine looks up against. In-memory, stateless, constructed fresh per request.

*Scope*
 - Produce the Expectations JSON keyed {{(ADC file, block, instance, entry) -> expected value}}.
 - Source expectations only from FCT + PDQ; never read ADC as a source of truth (ADC is the target).
 - Implement the three cross-correlation rules: project-block consistency (CFG_PROJECT_AEB / CFG_PROJECT_COM); dual-FMA consistency (RESET_TYPE / RESET_DELAY identical across CFG_SUPERVIS_FMA1 / FMA2); CFG_IP_SWITCH derivation from FCT {{redundantComPresent}}.
 - Group virtual references into channels for Check B forwarding expectations (internal, not exposed).

*Technical notes*
 - Stateless: method-local only, no caching, no shared singleton.
 - CFG_IP_SWITCH: {{redundantComPresent}} true -> add {{CFG_IP_SWITCH { IP_SWITCH: "1" }}}; false/absent -> omit. Distinct from CFG_IP_SWITCH_TIME (a CQ-IR key carried in {{pdqData}}).

*Dependencies & blockers*
 - Depends on VTF-333 (ComAebMap), VTF-331 / VTF-332 (parsed PDQ).
 - Feeds VTF-336 (engine lookup). Cross-correlation rule implementation tracked as B14.

*References*
Contract VTF-330.

*Acceptance criteria*
 - *Given* parsed FCT + PDQ, *When* the preprocessor runs, *Then* an Expectations JSON keyed by (file, block, instance, entry) is produced from baseline sources only.
 - *Given* divergent CFG_PROJECT_AEB / CFG_PROJECT_COM values, *When* the project-block rule runs, *Then* the check fails.
 - *Given* {{redundantComPresent}} true, *When* expectations are built, *Then* {{CFG_IP_SWITCH.IP_SWITCH}} = "1" is present.

*Test/BDD*
Cucumber: expectations-build, source-of-truth assertion (no ADC reads), each of the three cross-correlation rules.

########## VTF-338 (BE-08) — Cluster 1: CAN Segment ##########
==================================================================

*Context*
Validate per-AEB identity and SLCT_TIMEOUT, and virtual forwarding, against the FCT-derived baseline. The most fully specified cluster.

*Scope*
 - Check A: read [IDENTIFICATION] ID from each AEB ADC, look up in ComAebMap (miss -> ORPHANED); per in-scope block validate the referenced AEB id (miss -> FILE NOT FOUND); classify physical/virtual by segment membership; expected SLCT_TIMEOUT 0 (physical) / 1 (virtual); compare actual (2-7 -> INVALID SCOPE; other -> INVALID VALUE).
 - Check B: compute expected CFG_FWRD_ACD set per (homeCom, channel); evaluate as list-membership against actual entries.
 - Owns ID and SLCT_TIMEOUT across all in-scope blocks (CFG_ZP_FMA1/2, CFG_SECTION_OUT, CFG_CONTROL, CFG_SUPERVIS_FMA1/2, CFG_DATA_OUT).

*Technical notes*
 - Classification comes from ComAebMap segment membership, not the ADC value (the ADC value is the actual under test).
 - Socket numbering: socket = header - 32; Check B uses NW1 only.

*Dependencies & blockers*
 - Depends on VTF-336, VTF-335, VTF-333.

*References*
Contract VTF-330. Report sheet: Ethernet Details.

*Acceptance criteria*
 - *Given* an AEB whose ID is absent from ComAebMap, *When* Check A runs, *Then* ORPHANED is emitted.
 - *Given* a virtual reference (different segment), *When* expected SLCT_TIMEOUT is derived, *Then* it is 1 and compared to the ADC actual.
 - *Given* a homeCom file missing an expected forwarding entry, *When* Check B runs, *Then* the rule fails.

*Test/BDD*
Cucumber: Check A (orphaned, file-not-found, physical/virtual, invalid scope/value), Check B (forwarding membership).
